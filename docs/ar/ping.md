# Ping

## `ping` / `pg` — صدى ICMP

```
CMD> pg <ip|hostname>
CMD> pg 192.168.1.1
CMD> pg google.com
CMD> pg 0              # ping بفهرس netdiscover بعد تشغيل nd
```

يتطلّب اتصال WiFi فعّالًا.

---

## كيف يعمل

يرسل ping للهدف **باستمرار حتى تضغط `q`**. تعرض الشاشة تخطيطًا ثابتًا: نافذة متحرّكة بأحدث النتائج (رقم التسلسل + RTT، أو `timeout`)، وسطر إحصاءات حيّ (المُرسَل / المُستقبَل / نسبة الفقد) وأدنى/متوسّط/أقصى RTT.

```
[NET::PING]  192.168.1.1
-> 192.168.1.1
--------------------------------
[+] seq 4    2 ms
[-] seq 6    timeout
[+] seq 7    2 ms
--------------------------------
sent 7  recv 6  loss 14%
rtt 1/1/2 ms (min/avg/max)
q=stop
```

تُحَلّ أسماء DNS قبل الإرسال — `pg google.com` يحلّ الـ IP أوّلًا ثم يرسل ping. اضغط `q` في أي وقت للإيقاف.

---

## ملاحظات

- **اختصار الفهرس** — بعد `netdiscover` (`nd`)، أرسل ping بالفهرس: `pg 0` يرسل للمضيف الأوّل. وبعد `netspy` (`ns`)، استخدم البادئة `ns`: `pg ns3` يرسل لجهاز netspy رقم 3 (عمود `#` في جدول netspy). بلا حاجة لكتابة IP.
- **فقد الحزم > 0%** — قد يدلّ على تشويش لاسلكي، أو جدار حماية المضيف يُسقط ICMP، أو أن المضيف متوقّف.
- **RTT مرتفع جدًّا** — طبيعي لمضيفي الإنترنت (50–200 مِلّي ثانية)؛ وأقلّ من 5 مِلّي ثانية متوقّع لأهداف الشبكة المحلّية.
- **كل النتائج timeout** — المضيف متوقّف، أو يحجب ICMP، أو غير قابل للوصول من هذه الشبكة.
