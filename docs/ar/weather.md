# الطقس

## `weather` / `wx` — الأحوال الحالية (Open-Meteo، بلا مفتاح API)

يجلب الطقس الحالي لواجهة [الشاشة الرئيسية]({{ site.baseurl }}/home) من واجهة [Open-Meteo](https://open-meteo.com) — **مجانية وبلا مفتاح** (بلا مفتاح API، فلا شيء سرّي يُخزَّن على بطاقة SD).

> **لا يمكن معرفة الطقس دون اتصال.** فهو بيانات خادم حيّة. وتحديد GPS/الموقع يخبر الاستعلام *بمكانك* فقط — أمّا درجة الحرارة والأحوال الفعلية فتأتي من الشبكة. لذا يحتاج هذا إلى **WiFi** (`cw`).

```
CMD> wx                        # عرض الحالة (الموقع / الوحدات / آخر قراءة)
CMD> wx loc <lat> <lon>        # ضبط الموقع (حين لا يوجد تحديد GPS)
CMD> wx units metric|imperial  # °C أو °F
CMD> wx now                    # الجلب فورًا وعرض النتيجة
```

على **T-Deck Plus مع تحديد GPS يعمل هذا بلا أي إعداد** — بلا مفتاح، وبلا موقع تضبطه.

---

## الموقع — تلقائي، الأفضل مصدرًا أوّلًا

يختار `wx now` **أفضل** موقع متاح؛ ولا تضبط شيئًا عادةً:

1. **تحديد GPS** *(الأدقّ)* — على T-Deck **Plus**، يُستخدَم بمجرّد توفّر تحديد GPS.
2. **يدوي `wx loc <lat> <lon>`** — تجاوز صريح، إن ضبطت واحدًا.
3. **تحديد موقع عبر IP لـ WiFi** *(تقريبي، تلقائي)* — حين لا يوجد GPS/موقع يدوي، يستدلّ الجهاز على موقعه التقريبي من IP العامّ عبر `ip-api.com` (مجاني، بلا مفتاح). ويُخزَّن بعد أوّل استعلام.

فعلى Plus تحصل على GPS تلقائيًّا، وعلى اللوح الأساسي يحدّد موقعه تلقائيًّا عبر WiFi — و**`wx loc` تجاوز اختياري فقط، وليس مطلوبًا**.

> **ملاحظة خصوصية:** يرسل تحديد الموقع عبر IP عنوانك العامّ إلى `ip-api.com`. أمّا تحديد GPS أو `wx loc` اليدوي فيتجنّب هذا الطرف الثالث كلّيًّا.

---

## ملفّ الإعداد — `/config/weather.conf`

**يُنشَأ ذاتيًّا عند أوّل إقلاع** كقالب معلّق. ولأن Open-Meteo بلا مفتاح، فلا شيء سرّي — فقط (اختياريًّا) موقع:

```ini
# weather.conf — Al-Anqa weather (Open-Meteo, no API key), shown in the `home` launcher
# lat=31.9539
# lon=35.9106
units=metric   # or: imperial
```

- يُزيل المُحلّل التعليقات `#` والمسافات المحيطة.
- ضبط القيم بـ `wx loc` / `wx units` يعيد كتابة الملفّ.
- **بلا مفتاح API** يعني لا سرّ نصّي على البطاقة القابلة للإزالة — مكسب OPSEC صغير.

## كيف يجلب (آمن من GDMA)

يستخدم الطلب **HTTP عاديًّا** (`WiFiClient`) — إذ يخدم Open-Meteo الردّ نفسه بلا مفتاح عبر HTTP، وقراءة الطقس لا تحتاج سرّية. وأُسقِط HTTPS لأن تخصيص DRAM الداخلي لمصافحة TLS (نحو 30–40 KB) يفشل تحت الشاشة الرئيسية حيث تقيم صورة PSRAM كاملة وخطوط VLW: فالطقس يُجلَب جيّدًا من الأوامر لكنه يفشل داخل تطبيق الشاشة الرئيسية المتخفّي. أمّا HTTP العادي فبلا تلك الكلفة، فيعمل في الحالتين.

يعمل الطلب **فقط** من `wx now` ومن **دخول الشاشة الرئيسية** — لا من حلقة الإدخال الخلفية. وهذا مقصود: فـ `netspy`/`isoscan` يعملان بالارتباط مع الوضع المختلط، وأي جلب أثناء ذلك يُتلف نظام الملفّات/محرّك WiFi ([قاعدة GDMA]({{ site.baseurl }}/troubleshooting)). أمّا المُطلِق فشاشة تنكّر حميدة و WiFi خامل، فالجلب فيه آمن.

تُخزَّن آخر قراءة ناجحة في الذاكرة وتُعرَض حتى بعد سقوط WiFi (حتى إعادة التشغيل). وفاصل التحديث 15 دقيقة.
